CreateCatalogTable

Creates a new table registration within the Unity Catalog.

// Signature:
(instance) catalogName: string -> schemaName: string -> tableName: string -> polarsSchema: PolarsSchema -> tableType: Option<CatalogTableType> -> storageLocation: Option<string> -> Void

Parameters

Name Type Description
catalogName string The name of the catalog where the table will be created.
schemaName string The name of the schema (database) within the catalog.
tableName string The name of the table to be created.
polarsSchema PolarsSchema The structural definition of the table columns and data types via PolarsSchema.
tableType Option<CatalogTableType> The management type of the table. Managed: Unity Catalog manages both metadata and physical data. External: Unity Catalog manages metadata, but data resides at a specific storageLocation.
storageLocation Option<string> The physical URI for the table data (e.g., s3://my-bucket/path/). Required if tableType is set to External; typically null for Managed tables.

DeleteCatalogRecords

Deletes records from a Unity Catalog table that match the specified predicate. This operation is ACID-compliant and leverages the underlying Delta Lake protocol. If Deletion Vectors (DVs) are enabled on the table, it performs a metadata-only delete; otherwise, it performs a physical rewrite of the affected data files.

DeltaHistory

Retrieves the commit history (audit trail) for a Unity Catalog Delta table as a DataFrame. This includes metadata about who performed what operation, when it occurred, and what parameters were used.

// Signature:
(instance) catalogName: string -> schemaName: string -> tableName: string -> limit: Option<int> -> cloudOptions: Option<CloudOptions> -> DataFrame

Parameters

Name Type Description
catalogName string The name of the catalog (e.g., "main").
schemaName string The name of the schema/database (e.g., "default").
tableName string The name of the table to audit.
limit Option<int> The maximum number of history commits to retrieve. If 0, retrieves all available history.
cloudOptions Option<CloudOptions> Cloud-specific configurations and credentials resolved via Unity Catalog.

Returns

A DataFrame containing the flattened and formatted history of the table.

Note

Data Processing: The raw JSON history from the Delta log is automatically processed: Timestamps are cast to UTC Datetime. Complex fields like operationMetrics and operationParameters are unnested into flat columns. Columns are reordered to place essential information (version, timestamp, operation) at the beginning.

Note on Versioning: For standard DML operations, the version column might be null in the raw log; rows are sorted by version or timestamp in descending order (latest first) by default.

DeltaRestore

Restores a Unity Catalog Delta table to a previous state based on a version number or a timestamp. This operation is atomic and ACID-compliant.

// Signature:
(instance) catalogName: string -> schemaName: string -> tableName: string -> version: Option<UInt64> -> timestamp: Option<DateTime> -> ignoreMissingFiles: Option<bool> -> protocolDowngradeAllowed: Option<bool> -> cloudOptions: Option<CloudOptions> -> UInt64

Parameters

Name Type Description
catalogName string The name of the catalog (e.g., "main").
schemaName string The name of the schema/database (e.g., "default").
tableName string The name of the table to restore.
version Option<UInt64> The specific Delta table version to restore to. Mutually exclusive with timestamp.
timestamp Option<DateTime> The specific DateTime to restore the table state to. Mutually exclusive with version.
ignoreMissingFiles Option<bool> If true, allows the restore to proceed even if some underlying data files are missing from storage. Use with caution as this may result in a partial restoration.
protocolDowngradeAllowed Option<bool> If true, allows the table to be restored to a version that requires a lower protocol reader/writer version than the current one.
cloudOptions Option<CloudOptions> Cloud-specific configurations and credentials resolved via Unity Catalog.

Returns

The new version number of the table after the restore operation is committed.

Note

How it works: Instead of physically deleting newer data, Restore creates a new commit in the transaction log that reverts the table's metadata and file references to the target state.

Safety: This operation will fail if any required data files have been physically removed (e.g., by a Vacuum operation) unless ignoreMissingFiles is set to true.

DeltaVacuum

Physically deletes data files that are no longer referenced by the Delta table and are older than the specified retention threshold. This operation helps reduce storage costs and ensures compliance by removing historical data that is no longer needed.

// Signature:
(instance) catalogName: string -> schemaName: string -> tableName: string -> retentionHours: Option<int> -> enforceRetention: Option<bool> -> dryRun: Option<bool> -> vacuumModeFull: Option<bool> -> cloudOptions: Option<CloudOptions> -> int64

Parameters

Name Type Description
catalogName string The name of the catalog (e.g., "main").
schemaName string The name of the schema/database (e.g., "default").
tableName string The name of the table to vacuum.
retentionHours Option<int> The number of hours to retain historical files. Files modified within this window will not be deleted. If null, the table's default retention setting is used.
enforceRetention Option<bool> If true, the operation will fail if retentionHours is less than the table's minimum retention (usually 168h). Set to false only for emergency cleanup, at the risk of corrupting active readers.
dryRun Option<bool> If true, the method returns the number of files that would be deleted without actually removing them.
vacuumModeFull Option<bool> If true, performs a full scan of the object store to find unreferenced files. If false (Lite mode), uses the Delta log to identify files to be removed.
cloudOptions Option<CloudOptions> Cloud-specific configurations and credentials resolved via Unity Catalog.

Returns

The total number of physical files deleted from storage (or identified for deletion if dryRun is true).

Note

Warning: This is a destructive operation. Once files are vacuumed, you can no longer "Time Travel" to versions that relied on those files.

Retention Period: By default, Delta Lake prevents deleting files younger than 168 hours (7 days) to protect active readers and concurrent transactions.

OptimizeCatalogTable

Optimizes the storage layout of a Unity Catalog Delta table by compacting small files and optionally applying Z-Order clustering. This operation significantly improves read performance by reducing file-open overhead and enabling efficient data skipping.

// Signature:
(instance) catalogName: string -> schemaName: string -> tableName: string -> targetSizeMb: Option<int64> -> partitionFilters: Option<FSharpMap<string, string>> -> zOrderColumns: Option<Seq<string>> -> cloudOptions: Option<CloudOptions> -> int64

Parameters

Name Type Description
catalogName string The name of the catalog (e.g., "main").
schemaName string The name of the schema/database (e.g., "default").
tableName string The name of the table to optimize.
targetSizeMb Option<int64> The target size for the compacted Parquet files in Megabytes. Default is 128 MB.
partitionFilters Option<FSharpMap<string, string>> Optional filters to limit the optimization to specific partitions. If null, the entire table is processed.
zOrderColumns Option<Seq<string>> An optional collection of column names to use for Z-Order clustering.
cloudOptions Option<CloudOptions> Cloud-specific configurations, including storage credentials and retry logic.

Returns

The total number of files that were successfully compacted/optimized during the operation.

Note

Compaction: Groups small Parquet files into larger ones based on the target size.

Z-Ordering: If zOrderColumns are provided, the data is rearranged into multidimensional clusters.

Deletion Vector (DV) Materialization: If the table uses DVs, this operation physically removes any soft-deleted rows.
