AddFeature

Enables a specific feature on the Delta Table.

WARNING: Enabling features may upgrade the Delta Protocol version (e.g., to Reader v3 / Writer v7). Older readers may not be able to read the table after this operation.

// Signature:
path: string -> featureName: string -> allowProtocolIncrease: Option<bool> -> cloudOptions: Option<CloudOptions> -> Void

Parameters

Name Type Description
path string The root URI of the Delta table.
featureName string The name of the feature to enable (use DeltaTableFeatures constants).
allowProtocolIncrease Option<bool> If true, allows the operation to upgrade the table's Protocol Version if the feature requires it. If false, and the current protocol is too low, the operation will fail.
cloudOptions Option<CloudOptions> Cloud storage credentials.

Delete

Deletes rows from a Delta Lake table that match a given predicate.

By default, this operation performs a Copy-on-Write (CoW), meaning any underlying data files containing matching rows are entirely rewritten.

Note: If Deletion Vectors are enabled on the table, this operation automatically shifts to a Merge-on-Read (MoR) approach. Instead of expensive file rewrites, deleted rows are swiftly marked in a separate deletion vector file, which drastically improves deletion performance.

// Signature:
path: string -> predicate: Expr -> cloudOptions: Option<CloudOptions> -> Void

Parameters

Name Type Description
path string Path to the Delta table.
predicate Expr Filter expression to identify rows to delete.
cloudOptions Option<CloudOptions> Cloud storage configuration.

Optimize

Optimizes the layout of the Delta table by compacting small files (bin-packing) and optionally applying Z-Order clustering.

This operation significantly improves read performance by reducing the number of files and co-locating related data.

Note: If Deletion Vectors (DV) are enabled on the table, any soft-deleted rows tracked by the vectors will be physically removed (materialized) from the newly compacted Parquet files, effectively clearing the deletion vectors for the optimized partitions.

// Signature:
path: string -> targetSizeMb: Option<int64> -> partitionFilters: Option<Seq<Tuple<string, string>>> -> zOrderColumns: Option<Seq<string>> -> cloudOptions: Option<CloudOptions> -> int64

Parameters

Name Type Description
path string The root URI of the Delta table.
targetSizeMb Option<int64> The target file size in Megabytes for the compacted files (default: 128 MB).
partitionFilters Option<Seq<Tuple<string, string>>> Optional sequence of partition key-value pairs to restrict optimization to specific partitions.

Example: [ ("date", "2024-01-01") ]
zOrderColumns Option<Seq<string>> Optional sequence of column names to apply Z-Order clustering.

Z-Ordering co-locates data based on these columns, significantly speeding up queries that filter on them.
cloudOptions Option<CloudOptions> Cloud storage credentials and configuration.

Returns

The number of new data files created during the optimization process.

Restore

Restores the Delta table to a previous state defined by a specific version or timestamp.

Note: This operation creates a new commit (version) that reflects the state of the table at the target point.

// Signature:
path: string -> version: Option<UInt64> -> timestamp: Option<DateTime> -> ignoreMissingFiles: Option<bool> -> protocolDowngradeAllowed: Option<bool> -> cloudOptions: Option<CloudOptions> -> UInt64

Parameters

Name Type Description
path string The root URI of the Delta table.
version Option<UInt64> The specific version number to restore to. Set to null if restoring by timestamp.
timestamp Option<DateTime> The timestamp to restore to. Set to null if restoring by version.
ignoreMissingFiles Option<bool> If true, the restore operation will ignore missing files (e.g., those deleted by Vacuum). If false, it will fail if any required files are missing.
protocolDowngradeAllowed Option<bool> Whether to allow downgrading the Delta Protocol version during restore (rarely needed).
cloudOptions Option<CloudOptions> Cloud storage credentials.

Returns

The new version number of the table after the restore operation.

Vacuum

Recursively delete files and directories in the table that are no longer needed by the table for maintaining the transaction history.

// Signature:
path: string -> retentionHours: Option<int> -> enforceRetention: Option<bool> -> dryRun: Option<bool> -> vacuumModeFull: Option<bool> -> cloudOptions: Option<CloudOptions> -> int64

Parameters

Name Type Description
path string The root URI of the Delta table (e.g., "s3://bucket/table").
retentionHours Option<int> The retention threshold in hours. Files removed before this threshold will be deleted. Set to -1 to use the default retention period configured in the table (usually 168 hours / 7 days).
enforceRetention Option<bool> If true, prevents the vacuum command from deleting files that have not yet reached the retention threshold. Setting this to false allows forcing deletion of recent files (use with caution).
dryRun Option<bool> If true, simply returns the number of files that would be deleted, without actually deleting them.
vacuumModeFull Option<bool> Specifies the vacuum mode:

false (Lite): Only removes files that are explicitly referenced as removed in the transaction log. Faster.



true (Full): Scans the entire storage directory to find and remove any files not referenced in the transaction log (including orphan files from failed writes). Slower but more thorough.
cloudOptions Option<CloudOptions> Cloud storage credentials and configuration (e.g. AWS Keys, Azure Secrets).

Returns

The number of files deleted (or selected for deletion in dry-run mode).
