DeltaHistory ​

Retrieves the commit history (audit trail) for a Unity Catalog Delta table as a DataFrame. This includes metadata about who performed what operation, when it occurred, and what parameters were used.

fsharp
member DeltaHistory(
    catalogName: string,
    schemaName: string,
    tableName: string,
    ?limit: int,
    ?cloudOptions: CloudOptions
) : DataFrame

Parameters

NameTypeDescription
catalogNamestringThe name of the catalog (e.g., "main").
schemaNamestringThe name of the schema/database (e.g., "default").
tableNamestringThe name of the table to audit.
limitint (optional)The maximum number of history commits to retrieve. If 0, retrieves all available history.
cloudOptionsCloudOptions (optional)Cloud-specific configurations and credentials resolved via Unity Catalog.

Returns: A DataFrame containing the flattened and formatted history of the table.

NOTE

Data Processing: The raw JSON history from the Delta log is automatically processed:

  • Timestamps are cast to UTC DataType.Datetime.
  • Complex fields like operationMetrics and operationParameters are unnested into flat columns.
  • Columns are reordered to place essential information (version, timestamp, operation) at the beginning.

Note on Versioning: For standard DML operations, the version column might be null in the raw log; rows are sorted by version or timestamp in descending order (latest first) by default.

DeltaRestore ​

Restores a Unity Catalog Delta table to a previous state based on a version number or a timestamp. This operation is atomic and ACID-compliant.

fsharp
member DeltaRestore(
    catalogName: string,
    schemaName: string,
    tableName: string,
    ?version: uint64,
    ?timestamp: DateTime,
    ?ignoreMissingFiles: bool,
    ?protocolDowngradeAllowed: bool,
    ?cloudOptions: CloudOptions
) : uint64

Parameters

NameTypeDescription
catalogNamestringThe name of the catalog (e.g., "main").
schemaNamestringThe name of the schema/database (e.g., "default").
tableNamestringThe name of the table to restore.
versionuint64 (optional)The specific Delta table version to restore to. Mutually exclusive with timestamp.
timestampDateTime (optional)The specific DateTime to restore the table state to. Mutually exclusive with version.
ignoreMissingFilesbool (optional)If true, allows the restore to proceed even if some underlying data files are missing from storage. Use with caution as this may result in a partial restoration.
protocolDowngradeAllowedbool (optional)If true, allows the table to be restored to a version that requires a lower protocol reader/writer version than the current one.
cloudOptionsCloudOptions (optional)Cloud-specific configurations and credentials resolved via Unity Catalog.

Returns: The new version number of the table after the restore operation is committed.

NOTE

How it works: Instead of physically deleting newer data, Restore creates a new commit in the transaction log that reverts the table's metadata and file references to the target state.

Safety: This operation will fail if any required data files have been physically removed (e.g., by a Vacuum operation) unless ignoreMissingFiles is set to true.

DeltaVacuum ​

Physically deletes data files that are no longer referenced by the Delta table and are older than the specified retention threshold. This operation helps reduce storage costs and ensures compliance by removing historical data that is no longer needed.

fsharp
member DeltaVacuum(
    catalogName: string,
    schemaName: string,
    tableName: string,
    ?retentionHours: int,
    ?enforceRetention: bool,
    ?dryRun: bool,
    ?vacuumModeFull: bool,
    ?cloudOptions: CloudOptions
) : int64

Parameters

NameTypeDescription
catalogNamestringThe name of the catalog (e.g., "main").
schemaNamestringThe name of the schema/database (e.g., "default").
tableNamestringThe name of the table to vacuum.
retentionHoursint (optional)The number of hours to retain historical files. Files modified within this window will not be deleted. If null, the table's default retention setting is used.
enforceRetentionbool (optional)If true, the operation will fail if retentionHours is less than the table's minimum retention (usually 168h). Set to false only for emergency cleanup, at the risk of corrupting active readers.
dryRunbool (optional)If true, the method returns the number of files that would be deleted without actually removing them.
vacuumModeFullbool (optional)If true, performs a full scan of the object store to find unreferenced files. If false (Lite mode), uses the Delta log to identify files to be removed.
cloudOptionsCloudOptions (optional)Cloud-specific configurations and credentials resolved via Unity Catalog.

Returns: The total number of physical files deleted from storage (or identified for deletion if dryRun is true).

NOTE

Warning: This is a destructive operation. Once files are vacuumed, you can no longer "Time Travel" to versions that relied on those files.

Retention Period: By default, Delta Lake prevents deleting files younger than 168 hours (7 days) to protect active readers and concurrent transactions.

OptimizeCatalogTable ​

Optimizes the storage layout of a Unity Catalog Delta table by compacting small files and optionally applying Z-Order clustering. This operation significantly improves read performance by reducing file-open overhead and enabling efficient data skipping.

fsharp
member OptimizeCatalogTable(
    catalogName: string,
    schemaName: string,
    tableName: string,
    ?targetSizeMb: int64,
    ?partitionFilters: Map<string, string>,
    ?zOrderColumns: seq<string>,
    ?cloudOptions: CloudOptions
) : int64

Parameters

NameTypeDescription
catalogNamestringThe name of the catalog (e.g., "main").
schemaNamestringThe name of the schema/database (e.g., "default").
tableNamestringThe name of the table to optimize.
targetSizeMbint64 (optional)The target size for the compacted Parquet files in Megabytes. Default is 128 MB.
partitionFiltersMap<string, string> (optional)Optional filters to limit the optimization to specific partitions. If null, the entire table is processed.
zOrderColumnsseq<string> (optional)An optional collection of column names to use for Z-Order clustering.
cloudOptionsCloudOptions (optional)Cloud-specific configurations, including storage credentials and retry logic.

Returns: The total number of files that were successfully compacted/optimized during the operation.

NOTE

Compaction: Groups small Parquet files into larger ones based on the target size.

Z-Ordering: If zOrderColumns are provided, the data is rearranged into multidimensional clusters.

Deletion Vector (DV) Materialization: If the table uses DVs, this operation physically removes any soft-deleted rows.
